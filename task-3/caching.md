# Стратегия кеширования

## Что кешировать
1. Кампании
2. Бюджеты, балансы
3. Ставки на каждый аукцион
4. Победители аукциона

### Что не кешировать
1. Bid-request/response, т.к. уникальны на каждый запрос
2. Финансовые балансы «на запись», т.к. появится риск двойного списания
3. Транзакции

## Где разместить Redis
1. Hot-path Redis (Bidding Service и Delivery Dervice). Необходим отдельный кластер, т.к. необходима максимальная производительность и критичен для SLA 80 мс.
2. Back-office Redis (для Campaign Servie, Analytics Service, кабинета рекламодателя). Менее нагруженный. Не на hor path - деградация не роняет аукцион.

## TTL и стратегия инвалидации
Настройка TTL по правилу: часто меняющиеся данные (бюджеты, кампании) короткий TTL + event-driven обновление. Редко меняющиеся (аналитика) длинный TTL, обновление по истечению TTL.

## Прогрев кеша
1. При старте сервиса
2. Периодическое обновление. Например раз в 10 минут обновляется топ компаний для fallbackhandler
3. При деплое новой версии
4. После сбоя Redis
