# Масштабирование БД

## Сервис ставок (Bidding Service)
Своей БД у сервиса нет. Он работает только с Redis, чтобы уложиться в SLA 80 мс. Необходимо использовать Redis Cluster и Redis Sentinel. CQRS уже реализован: запись-только кэш победителей, чтение - проекции кампаний и балансов.

## Сервис кампаний (Campaign Service)
Масштабируется горизонтально. PostgreSQL работает по схеме master-slave: master принимает запись (создание/редактирование кампаний), slave - чтение для кабинета и API. Шардирование пока не требуется, но при росте числа рекламодателей использовать шардирование по ключу идентификатора рекламодателя, например. Read replicas отдельные для UI и API.

## Сервис статистики (Statistics Service)
Масштабируется горизонтально на ClickHouse. Шардирование по дате. CQRS излишен, т.к. идет только запись событий, а чтение через Kafka

## Сервис аналитики (Analytics Service)
Масштабируется горизонтально. Репликация master-slave. Шардирование не нужно, т.к. отчётов немного. СQRS уместен

## Сервис финансов (Financial Service)
Масштабируется горизонтально. Репликация master-slave. Шардирование если нагрузка возрастет. Read replicas для отчётов по балансам, дашбордов и аудита. CQRS - да. Дополнительно — идемпотентность идентификатору
